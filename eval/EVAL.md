# NL2SQL Evaluation Framework

## Overview

This evaluation framework measures the accuracy, efficiency, and cost-effectiveness of the NL2SQL agentic system across three configurations:

- **Finetuned-only**: Uses only the finetuned HuggingFace model (single attempt)
- **Superior-only**: Uses only the superior model via OmniRoute (single attempt)
- **Agentic**: Full multi-step system with error correction loop (up to 3 attempts)

## Methodology

### Test Dataset

60 test cases spanning two domains:

1. **E-commerce Database** (35 cases)
   - Customers, products, orders tables
   - Queries ranging from simple SELECT to complex joins and subqueries

2. **HR System Database** (25 cases)
   - Departments, employees, payroll tables
   - Aggregations, self-joins, date filters, GROUP BY HAVING

### Evaluation Criteria

**Execution Equivalence**: A query is marked correct if its result set matches the expected result (order-agnostic, sorted comparison).

**Cost Tracking**: 
- Finetuned model: $0.00 (free tier)
- Superior/Judge models: Token-based estimation using Claude Sonnet pricing ($3/M input, $15/M output)

### Test Environment

- Database: SQLite 3.x
- Execution: Docker sandbox (isolated, read-only)
- Comparison: Result set matching after sorting

## How to Run

### Prerequisites

1. Set up environment variables in `.env`:
   ```
   HF_ENDPOINT=<your-huggingface-endpoint>
   HF_TOKEN=<your-token>
   OMNIROUTE_URL=<omniroute-url>
   OMNIROUTE_GEN_MODEL=claude-sonnet
   OMNIROUTE_JUDGE_MODEL=claude-sonnet
   ```

2. Ensure Docker is running (for sandbox execution)

3. Install dependencies:
   ```bash
   pip install -r requirements.txt
   ```

### Running Evaluations

**Single mode**:
```bash
python eval/run_eval.py --mode agentic
```

**All modes**:
```bash
for mode in finetuned superior agentic; do
  python eval/run_eval.py --mode $mode
done
```

**Custom output path**:
```bash
python eval/run_eval.py --mode agentic --output results/my_run.csv
```

### Analyzing Results

```bash
python eval/analyze.py
```

This script:
- Loads the latest result CSV for each mode
- Computes accuracy, cost, and timing statistics
- Identifies self-correction examples
- Prints a comparison table

### Result Files

Results are saved in `eval/results/`:
- `finetuned_YYYYMMDD.csv`
- `superior_YYYYMMDD.csv`
- `agentic_YYYYMMDD.csv`

Each CSV contains:
- `test_id`, `question`, `expected_sql`, `final_sql`
- `correct` (boolean)
- `attempts`, `finetuned_calls`, `superior_calls`, `judge_calls`
- `time_sec`, `cost_usd`
- `error` (if failed)

## Extending the Evaluation

### Adding Test Cases

Edit `eval/datasets/test_cases.csv`:

```csv
id,question,expected_sql,database,notes
61,Your question?,SELECT ...,ecommerce,Description
```

### Adding Databases

1. Create new database in `eval/datasets/`:
   ```python
   # In generate_db.py
   def create_my_db():
       conn = sqlite3.connect("my_db.db")
       # ... create tables
   ```

2. Add test cases referencing the new database name

### Custom Metrics

Modify `eval/analyze.py` to compute additional statistics:
- Error categorization (syntax vs logic vs timeout)
- Performance by query complexity
- Token usage breakdown
